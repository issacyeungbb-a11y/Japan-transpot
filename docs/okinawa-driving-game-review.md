# 沖繩自駕駕駛練習遊戲——獨立第三方全面評審報告

評審日期：2026-07-03
評審對象：本倉庫 `main` 系列現行版本（27 關統一練習系列，React + Phaser 3 俯視 2D）
評審角色：駕駛模擬遊戲設計顧問／道路安全及駕駛訓練顧問／沖繩自駕情境研究員／遊戲體驗及操作介面評審員

本報告全部基於實際代碼檢視（`src/data/scenarios/driving.ts`、`src/data/scenarios/enhance.ts`、`src/game/scenes/ScenarioScene.ts`、`src/data/trafficRules.ts`、`src/ui/**`、`src/store/gameStore.ts`），並以可核實的日本官方法規條文及公開資料為準。凡未能核實的內容均明確標示【需核實】。

## 1. 整體評價

**總評：規則教學紮實、駕駛訓練失真。目前是一款優秀的「日本交通規則情境測驗遊戲」，但距離「能把技能轉移到沖繩實際駕駛」的訓練工具仍有明顯差距。**

- 法規內容（紅燈禁右轉、箭頭信號、止まれ完全停車、右轉讓對向、行人絕對優先、左方優先、環狀交差點讓環內車、巴士專用線、ETC 20km/h、沖繩自動車道 80km/h）選題準確、條文引用基本正確，且全部指向沖繩租車遊客的真實高風險場景。
- 但車輛物理（煞車力約為真車 4 倍）、自動起步兼油門自動封頂（玩家實際上無需管理速度）、30km/h 以下滾過斑馬線不算違規、上帝視角無視線遮蔽等設計，會令玩家建立**與現實相反的習慣**（負遷移），這在駕駛訓練工具中比「內容不足」更嚴重。
- 訓練閉環缺失：失敗後直接進入下一關、無重試機制、評分只有「難度×連擊」單一維度，無法驅動針對性重複練習。
- 27 關全部複用同一個路口幾何，缺乏泊車／倒車、夜間、突發事件、連續路線駕駛，覆蓋面對照「赴沖繩自駕前訓練」的目標仍有約四成空白。

結論：**架構良好（情境資料驅動、NPC 反應式行為、弱項分析已具雛形），值得投資改造而非重寫。** 優先次序應為：先消除負遷移 → 再補訓練閉環 → 然後擴充內容 → 最後打磨表現。

## 2. 現有設計的主要優點

1. **法規選題精準**：27 關覆蓋外地租車客在日本最常犯的違規（一時不停止、紅燈右轉、搶黃燈、右轉不讓對向、斑馬線不讓行人），每關附 `lawArticle` 條文引用及 `commonMistake` 常見錯誤，方向完全正確。
2. **規則引擎正確**（`trafficRules.ts`）：紅／黃＝停止、箭頭凌駕主燈且只准箭頭方向、紅閃＝一時停止後可行、黃閃＝注意行進，與道路交通法第7条・施行令第2条一致。
3. **沖繩在地化考究**：
   - 沖繩自動車道最高 80km/h（已核實：那霸IC–許田IC，全線 80km/h）。
   - 無平交道關卡並在 README 說明原因（ゆいレール為高架單軌，無平交道）——正確的「不做什麼」決策。
   - 環狀交差點規則（入環不打燈、出環前打左燈、順時針、讓環內車）與 JAF／読谷村公告一致；沖繩糸滿確有 roundabout（2015 年糸滿ロータリー改建，縣內首個）。
   - 巴士專用線、ETC 閘、狹路會車、觀光區行人都是沖繩自駕的真實痛點。
4. **情境資料驅動架構**：`Scenario` 型別 + `enhanceScenario()` 自動補環境交通，關卡以資料描述，新增/重排成本低——是後續擴充的良好地基。
5. **NPC 反應式行為系統**：cruise/yield/aggressive/turner/random 五種行為、確定性隨機種子（同關卡可重現）、煞車燈與方向燈顯示意圖——超出同類小品遊戲的水準。
6. **盲點確認抽象**：`👀左後/右後` 按鈕＋滑動手勢喚出後方視野插圖，插圖會標示「有二輪車／安全」，是俯視視角下訓練「確認」行為的聰明折衷。
7. **弱項分析雛形**：結算頁按失敗原因統計並給出針對性建議文字（`REASON_ADVICE`），已是「錯誤→練習方向」閉環的正確起點。
8. **即時失敗橫幅**：失敗瞬間場景內顯示中文原因（衝燈／未完全停車…），先於 React 彈窗，回饋延遲低。
9. **評分不以完成時間計**：`calcScore` 不含時間項，避免鼓勵搶快——符合訓練目標。
10. **雙語（繁中／日文）全量覆蓋**，介面按鈕大、支援觸控長按與鍵盤，行動裝置可用性良好。

## 3. 現有設計的主要問題（總覽）

按危害排序，詳細六欄分析見第 5 節（P-xx 編號對應）：

**A 類——會造成負遷移（練完反而更危險）**
- P-01 煞車減速度 ≈3.8g，50km/h 約 2.6 米內停定（真車濕地需 20 米以上）
- P-02 自動以 50km/h 起步＋油門自動封頂於限速——玩家全程無需管理速度，`speeding` 判定實際上不可能觸發
- P-03 斑馬線有行人時，只要低於 30km/h（`YIELD_CREEP_SPEED=72px/s`）滾過去不算違規——法第38条要求一時停止
- P-04 「完全停車」判定：距停止線任意遠停一下都算、且 5km/h 以下即算停定
- P-07 俯視上帝視角無任何視線遮蔽——「停下來確認」失去存在理由
- P-14 紅燈＋右箭頭關卡中對向直行車照樣穿越路口、且要求玩家讓行——與信號相位邏輯矛盾

**B 類——訓練閉環缺失**
- P-05 失敗後直接下一關，無重試；可以全敗「通關」
- P-09 評分只有 難度×連擊，無安全／觀察／速度／讓行等維度
- P-06 無方向指示燈（打燈）操作
- P-08 盲點確認僅 1/27 關啟用；漏確認而剛好無車時靜默通過；`no_safety_check` 為死代碼
- P-26 錯誤回饋為關卡級靜態文字，不指出錯誤位置，通過與失敗看到同一段講解

**C 類——內容覆蓋缺口**
- P-10 泊車／倒車完全缺失（連倒車檔都沒有）
- P-11 突發事件缺失：前車急停、救護車、道路工程、錯過路口、導航改道、停車場滿位全部沒有
- P-12 夜間／逆光／霧（`visibility`）、坡道（`gradient`）、側風（`wind`）欄位已定義但場景從未實作
- P-13 車道選擇不評分：`laneCount`、`hasRightTurnLane` 場景端未使用；`illegal_overtake`、`failed_to_slow` 為死代碼
- P-19 27 關全部同一路口幾何、同一南向北進場，無連續路線、無導航

**D 類——結構與物理**
- P-18 難度1只有 2 關且已含交通，無零壓力操作熟習關
- P-20 燈號時序固定且短（如 3.2 秒轉青）——玩家背時間而非讀燈
- P-21 右轉讓對向（第37条，日本最重要右轉規則）遲至第 14 關，其前已有兩個右轉關
- P-23 車體比例過大（車寬約佔車道 80%），距離判斷失真；圓形碰撞對巴士／貨車嚴重失真
- P-24 高速時轉向過敏（80km/h 轉彎半徑僅約 9 米）
- P-25 「狹路」實際換算約 6.5 米，並非單車寬

**E 類——正確性與工程衛生**
- P-15 信號燈畫成直式；日本標準車用信號為橫式（紅燈在右端）
- P-16 巴士專用線無時段概念（現實為平日早晚繁忙時段、多線道最左第1車線；週日假日不實施）
- P-17 狹路會車引用「第18条・第27条」偏弱（第27条為被追及讓道義務）【需法規核實後改引】
- P-27 結算頁「最高連擊」實為「最終連擊」（最後一關失敗即顯示 0）
- P-28 無進度保存，刷新即失去全部記錄
- P-29 語言標籤 `zh-TW` 實為粵語（香港）文本
- P-30 README 聲稱「左轉關卡需左後盲點確認」與實作不符；`signs`、`decisionNodes`、`skewed`、`tunnel` 等為死欄位

## 5. 各項具體修改建議（每項六欄）

### P-01 煞車物理超現實 — 優先度 P0
- **現有問題**：`BRAKE_DECEL = 320 px/s²`。按遊戲比例（120px/s = 50km/h → 1px ≈ 0.116m）折合約 37 m/s² ≈ 3.8g；50km/h 至靜止僅需約 2.6 米。真車乾地極限約 1g，50km/h 制動距離 10–14 米，沖繩濕滑路面更長。
- **問題原因**：手感調參以「好玩、可救場」為準，未按物理換算校正。
- **對玩家訓練的影響**：玩家學會「最後一刻踩死煞車一定停得到」，是駕訓中最危險的單一負遷移；雨天關卡（×0.55 仍約 2g）同樣傳遞錯誤預期。
- **具體修正方法**：`ScenarioScene.ts` 中 `BRAKE_DECEL` 320→**85**（≈1g）、`RAIN_BRAKE_FACTOR` 0.55→**0.6**、`COAST_FRICTION` 50→**30**；同步把各關 NPC `startAtMs`/`speed` 重新校時（受影響最大：4、7、13、17、19、20 各關）；新增一個「煞車距離體驗」教學關（直路，於指定標記前從 40km/h 停定，畫出本次制動距離供對比）。
- **修改優先程度**：P0（最高）。
- **預期改善效果**：玩家被迫提前收油、提前輕煞——與現實一致的預判習慣；黃燈抉擇關（17）由「反應測試」變成真正的「距離—速度判斷」訓練。

### P-02 自動起步＋油門自動封頂，速度管理零訓練 — 優先度 P0
- **現有問題**：`onStartDriving` 直接把車速設為 min(50km/h, 限速)；`maxSpeedPx` 把油門上限鎖在「限速＋容差內」，因此 `speeding` 判定（超限 18% 持續 1.6 秒）在物理上不可能達成，屬死代碼；玩家也從不練起步。
- **問題原因**：為降低上手門檻，把「守限速」外包給物理引擎。
- **對玩家訓練的影響**：速度紀律完全沒有被訓練——現實中租車不會替你封頂；學校區 30km/h 一關實為「系統自動幫你 30」，學習效果為零。
- **具體修正方法**：(1) 起步速度改 0，保留油門加速（`ACCEL` 建議 70→50 px/s²，折合 0–50km/h 約 3.5 秒）；(2) `maxSpeedPx` 一律用全域 `MAX_SPEED`（或按路型 60/80/100 物理上限），刪除按限速封頂；(3) 保留現有超速容差判定（即刻生效，變成真判定）；(4) HUD 限速牌加超速時閃爍。
- **修改優先程度**：P0。
- **預期改善效果**：`speeding` 由死代碼變成核心評分維度；學校區、狹路、雨天關的「提前減速」成為玩家主動行為。

### P-03 行人讓行可低速滾過 — 優先度 P0
- **現有問題**：`YIELD_CREEP_SPEED = 72px/s`（30km/h）。行人正在斑馬線上，玩家以 29km/h 通過衝突區不觸發 `failed_to_yield`（只要沒撞到）。
- **問題原因**：為避免誤判「小心慢行也被罰」，把免罰門檻設得過寬。
- **對玩家訓練的影響**：法第38条要求橫斷歩道有行人通行時**一時停止**；日本警方近年重點取締。玩家練成「減速繞過行人」的習慣，在日本屬明確違規，也危險。
- **具體修正方法**：衝突對象為行人時，門檻由 72 降至 **24px/s（10km/h）**，且行人位於本車道正前方 60px 內時要求完全停止（`speed < STOP_EPS`）；對車輛讓行維持 30km/h 緩行豁免（匯入空檔判斷允許緩滾屬合理）。
- **修改優先程度**：P0。
- **預期改善效果**：與第38条一致；「見行人＝停定」形成條件反射，是本遊戲最值得帶去沖繩的單一習慣。

### P-04 一時停止判定寬鬆 — 優先度 P0
- **現有問題**：(a) 在停止線後方任意位置（哪怕 300px 外）停一下即記 `hasStopped`；(b) `STOP_EPS = 12px/s ≈ 5km/h` 即算「完全停車」。
- **問題原因**：判定只查「速度曾低於閾值且未過線」，未約束位置。
- **對玩家訓練的影響**：現實中一時不停止是租車客最常被取締項目（遊戲文案自己也這樣寫）；「遠處虛停＋滑行過線」壞習慣直接對應真實罰單。
- **具體修正方法**：`hasStopped` 加位置窗：`STOP_LINE_Y < car.y < STOP_LINE_Y + 90`（約兩個車身內）；`STOP_EPS` 用於一時停止判定時降為 **4px/s**（其餘用途維持 12 以免誤傷）；停定滿 0.6 秒才記為有效停車（新增計時），並在 HUD 顯示「✓已停定」提示。
- **修改優先程度**：P0。
- **預期改善效果**：學到「線前、停穩、數一下、左右確認」完整流程，而非「碰一下煞車」。

### P-05 失敗後無重試、可全敗通關 — 優先度 P0
- **現有問題**：`FeedbackModal` 只有「下一關」；`handleNext` 一律 `nextScenario()`。錯誤沒有被立即重練。
- **問題原因**：沿用測驗遊戲流程（答錯講解後出下一題）。
- **對玩家訓練的影響**：技能學習需要「錯誤→修正→立即重做」閉環；現在錯誤只留下一行統計，重複練習全靠玩家自律。
- **具體修正方法**：(1) `FeedbackModal` 失敗時主按鈕改「再試一次」（重發 `START_SCENARIO` 同關），次按鈕「跳過」；(2) 訓練模式下同關未通過不推進 `currentIndex`，連錯 3 次才允許跳過並標記「待重練」；(3) 結算頁弱項卡加「針對練習」按鈕：一鍵開 3 連發同類關卡（按 `category`/failure reason 過濾）。
- **修改優先程度**：P0。
- **預期改善效果**：訓練閉環成立；「重複練習」由建議變成機制。

### P-06 無方向指示燈操作 — 優先度 P0
- **現有問題**：玩家輸入只有油門/煞車/左右/回望，沒有打燈；NPC 反而會打燈。
- **問題原因**：控制面板簡化。
- **對玩家訓練的影響**：日本要求右左轉 30 米前、變線 3 秒前打燈（第53条・施行令第21条【表述需核實】）；右軚車撥桿在右側、港外司機常撥成雨刮——這正是本遊戲目標用戶的痛點，卻完全沒練。
- **具體修正方法**：(1) `inputState` 加 `signalLeft/signalRight`；`DrivingControls` 在轉向鍵上方加兩顆撥燈鍵（點按切換，轉向完成自動回位）；(2) 玩家車渲染加閃爍燈；(3) 評分：進入路口前未打燈完成轉向→新 `OutcomeReason: 'no_signal'`（首兩次警告扣觀察分，第三次起判失敗）；(4) 新增一個純打燈教學關。
- **修改優先程度**：P0。
- **預期改善效果**：把「轉彎=先打燈」植入操作序列；補上日本駕駛文化中最基本的溝通行為。

### P-07 上帝視角無視線遮蔽 — 優先度 P1（機制影響 P0 級，工程量較大故列 P1）
- **現有問題**：俯視鏡頭下玩家永遠看見全部路口與來車，建築物純裝飾。「停低慢慢探頭確認」的文案與機制脫節。
- **問題原因**：俯視 2D 天然全知；未做遮蔽渲染。
- **對玩家訓練的影響**：整個「確認文化」（日本駕訓核心）無法成立——玩家不需要停也看得到，等於用答案卷考試。
- **具體修正方法**：以玩家車為光源做 2D 陰影（Phaser 可用 `Phaser.Geom` 射線＋多邊形遮罩，或簡化為「路口四角遮蔽矩形，車頭越過停止線多少 px 就揭開多少」）；在 stop-sign／無號誌／停車場出口關（8、13、19、26）啟用；被遮蔽區的 NPC 不渲染（僅在露出後出現）；同步加「カーブミラー」道具：接近時顯示小圓鏡插圖預告橫向來車（複用現有 glance inset 元件）。
- **修改優先程度**：P1。
- **預期改善效果**：「先停→再探→確認→通過」變成獲勝的唯一策略；這是把本遊戲從測驗變成訓練器的關鍵一步。
- **美術執行**：遮蔽用 60% 黑色多邊形＋邊緣羽化；反射鏡為橙框圓鏡，鏡內以簡化色塊表示來車方向。

### P-08 盲點確認覆蓋不足、判定靜默 — 優先度 P1
- **現有問題**：`safetyCheck` 僅 roundabout 一關設定；README 聲稱所有左轉關都要求左後確認，不符；漏確認但剛好無車→靜默通過；專用 `no_safety_check` 原因從未觸發（實際回傳 `failed_to_yield`）。
- **問題原因**：功能做了一半；判定「無威脅即免查」。
- **對玩家訓練的影響**：巻き込み（左轉捲入二輪車）是日本典型事故型態；「有車才需要看」邏輯上不成立——看了才知道有沒有車。
- **具體修正方法**：(1) 所有左轉關（1、3、5、8、10、13、18、19）批量加 `safetyCheck: { blindSpotLeft: true }`（可在 `enhanceScenario` 按 `maneuver==='left'` 自動注入）；(2) 判定改為：未確認即轉向→無論有無威脅，都記 `no_safety_check`（有威脅時判失敗，無威脅時扣觀察分並於回饋標註「這次好彩無車」）；(3) 右轉關要求出發前右後確認一次。
- **修改優先程度**：P1。
- **預期改善效果**：確認變成無條件習慣；`no_safety_check` 死代碼復活並成為觀察分數據源。

### P-09 評分單一維度 — 優先度 P1
- **現有問題**：`calcScore = 100 × difficulty × streak倍率`，僅乘連擊；成功/失敗二值。
- **問題原因**：沿用街機式計分。
- **對玩家訓練的影響**：連擊獎勵鼓勵「求穩過關」而非「做對每個子行為」；玩家不知道自己「過了但過得差」。
- **具體修正方法**：場景已有全部所需信號，新增逐關五維評分（0–100）：**安全**（最小TTC、與NPC最近距離）、**法規**（停線/信號/讓行事件）、**觀察**（盲點確認、停定時長、【P-07 完成後】探頭行為）、**速度**（超速時長、進彎速度、急煞次數＝單幀減速>60px/s² 計數）、**決斷**（可通行空檔出現至起步的延遲）。實作：`ScenarioScene` 增 `metrics` 物件逐幀累計，`resolve()` 一併 emit；`AnswerRecord` 擴欄位；結算頁畫五維雷達（SVG 即可）。星級改按五維平均。
- **修改優先程度**：P1。
- **預期改善效果**：「過關但速度分 C」給出明確重練方向；弱項分析從失敗原因統計升級為能力畫像。

### P-10 泊車／倒車缺失 — 優先度 P1
- **現有問題**：無倒車檔、無泊車關；「停車場」只練出口左轉。
- **問題原因**：物理模型只有前進。
- **對玩家訓練的影響**：沖繩自駕每天泊車 3–5 次（飯店、景點、便利店），倒車入位為日本主流；這是使用者最常求助的技能之一，完全空白。
- **具體修正方法**：(1) 物理：速度允許負值（煞車鍵在停定後長按 0.5 秒進入 R 檔，HUD 顯示「R」），倒車限速 10km/h，轉向反向生效；(2) 新路型 `parking-lot`：繪製 3–4 個泊位＋兩側已停車輛，目標區為泊位框，完成條件＝車身四角全部入框且停定（用車身 OBB 判定，見 P-23）；(3) 三個新關：直角倒車入位（空場）→ 兩側有車倒車入位 → 滿位巡場（前兩排全滿，須繞至後排，訓練「滿位不慌」）；(4) 倒車時自動顯示後方視野插圖（複用 glance inset 放大版）。
- **修改優先程度**：P1。
- **預期改善效果**：填補最大內容缺口；車身尺寸感（P-23 修正後）在泊位中獲得最直接的訓練。

### P-11 突發事件缺失 — 優先度 P1
- **現有問題**：無前車急停、救護車、道路工程、錯過路口、導航改道、臨時封路。
- **問題原因**：NPC 行為系統已支援（aggressive/turner），但無關卡使用這些做突發劇本。
- **對玩家訓練的影響**：使用者需求書明確要求「訓練安全、冷靜、合規的反應，而非反應速度」——目前唯一接近的是黃燈抉擇。
- **具體修正方法**（各為一個新關，全部可用現有資料結構＋少量場景代碼）：
  - **前車急停**：lead NPC 在玩家跟車 3 秒後 `NPC_BRAKE_DECEL` 急停（新 NPC 行為 `'suddenstop'`，觸發條件＝玩家距離<160px）；評分看跟車距離是否≥2 秒車距，撞上＝collision，保持距離平穩停下＝過關。
  - **救護車讓行**：新 NPC variant `'ambulance'`（白車紅線＋閃燈動畫＋螢幕邊緣紅藍光暈提示），從後方接近；正確行為＝打左燈靠左減速/停車（判定：車貼近左緣且速度<10km/h 直至救護車通過）；依道路交通法第40条。
  - **道路工程**：直路關卡右前方置雪糕筒陣＋「工事中」牌，須提前打右燈跨中線繞行再回線；對向有車時須等待（複用 yieldToVehicles）。
  - **錯過路口／導航改道**：頂部導航條顯示「下個路口右轉」，行進中改為「重新計算…直行後左轉」；評分＝不急扭軚、不停在路中，按新指示完成（判定路徑即可）；回饋強調「錯過就錯過，切勿路口急切線——去下一個迴轉位」。
- **修改優先程度**：P1。
- **預期改善效果**：由「規則測驗」擴展到「應變訓練」；四關均訓練冷靜程序而非反應速度（評分掛在平穩度與程序正確，不掛時間）。

### P-12 夜間／逆光未實作 — 優先度 P1
- **現有問題**：`visibility: 'night' | 'fog' | 'glare'` 型別存在、零使用。
- **問題原因**：功能預留未完成。
- **對玩家訓練的影響**：沖繩東西向沿海路段晨昏逆光強烈、郊區夜間照明稀少，是租車客的真實風險；遊戲全關同一光照。
- **具體修正方法**：(1) `night`：全場 70% 深藍遮罩＋玩家車頭燈錐形透光（Phaser mask），NPC 只在燈錐與路燈圈內清晰；行人穿深色衣（現有 pedestrian 顏色改暗）；(2) `glare`：畫面上緣加白色漸層光暈＋對向來車位置延遲 300ms 才渲染（模擬看不清）；(3) 先各做一關：夜間郊區直路（行人橫過）＋傍晚逆光右轉（對向車難見）——複用現有關卡幾何改 `visibility` 即可。
- **修改優先程度**：P1。
- **預期改善效果**：教「看不清＝減速」，環境維度從 1 種（雨）擴至 3 種。

### P-13 車道選擇不評分、兩個死代碼原因 — 優先度 P1
- **現有問題**：`laneCount`/`hasRightTurnLane` 僅存在於第 27 關資料，場景不使用；multilane 路面無右轉專用格；`failed_to_slow`、`illegal_overtake` 從未觸發。
- **問題原因**：功能未完成。
- **對玩家訓練的影響**：「提早入右轉線」是關卡文案的教學重點，但走錯線不會有任何後果——文案與機制脫節。
- **具體修正方法**：(1) multilane 路型繪右轉專用格（路面「右折」字＋箭頭），停止線處檢查 `car.x`：要右轉但在直行線→新原因 `'wrong_lane'`（或複用 `wrong_way`，建議新增）；(2) `failed_to_slow`：在 `signs:['slow']` 或學校區關，通過指定徐行區段（y 區間）速度>20km/h 即觸發；順帶把 `signs` 欄位真正渲染成路邊標誌（「徐行」藍底白字牌）；(3) `illegal_overtake`：狹路/黃實線路段跨中線超越前車即觸發（判定：`car.x` 越過中線且前方 120px 內有同向 NPC）。
- **修改優先程度**：P1。
- **預期改善效果**：三個已寫好文案的失敗原因全部激活；第 27 關名副其實。

### P-14 紅＋右箭頭關卡的對向車矛盾 — 優先度 P0（改動小）
- **現有問題**：第 6 關（arrow-right-only）主燈紅＋右箭頭時，仍有對向直行車穿越路口（資料內 `oncoming1` ＋ `enhance` 因 `maneuver==='right'` 自動注入 aggressive 對向車），並要求玩家讓行。真實信號相位下，右箭頭亮起時對向必為紅燈。
- **問題原因**：`needsVehicleYield()` 對所有右轉一刀切；`intersectionTraffic()` 只對「玩家綠燈」抑制橫向車，未對「箭頭保護相位」抑制對向車。
- **對玩家訓練的影響**：教出「右箭頭時仍要讓對向」的錯誤模型——現實中在保護相位猶豫不前，反而阻塞右轉車流；也暗示對向恆常衝紅燈。
- **具體修正方法**：(1) `driving.ts` 第 6 關移除 `oncoming1`（或改為在箭頭亮前已通過路口的時序）；(2) `enhance.ts`：`needsVehicleYield` 排除「light 為 arrow 且 activeArrows 含 right」的情況；`intersectionTraffic` 在同條件下不注入對向 ambient；(3) 回饋文案加一句「右箭頭期間對向為紅燈，可依序通過，但仍須留意衝燈車輛」。
- **修改優先程度**：P0。
- **預期改善效果**：信號相位邏輯自洽；玩家學到「保護右轉」的正確含義。

### P-15 信號燈直式（應為橫式） — 優先度 P2
- **現有問題**：場景與 SVG 信號皆為直式三燈；日本標準車用信號為橫式、紅燈在最右（直式主要用於多雪地區，沖繩不適用）。
- **問題原因**：美術沿用通用範本。
- **對玩家訓練的影響**：燈位辨識（尤其強光下靠位置認燈）與現實不符；屬視覺真實性問題，非規則錯誤。
- **具體修正方法**：`renderLamp()`／`TrafficLightSVG` 改橫式：燈箱 74×26、左→右＝綠/黃/紅；箭頭燈附於主燈箱下方（符合日本常見「主燈＋下排箭頭」構型）；燈桿改懸臂式（日本路口常見懸出路面上方）。
- **修改優先程度**：P2。
- **預期改善效果**：到埗後第一眼即認得燈具；美術工作量約 1–2 天。

### P-16 巴士專用線無時段概念 — 優先度 P1
- **現有問題**：藍色車道全時段禁入，玩家學到「見藍色就不入」。
- **問題原因**：簡化。
- **對玩家訓練的影響**：現實是「平日早晚時段禁入，其他時間可行」；全時段禁入的錯誤模型會令玩家在非管制時段仍不敢用左線，反而造成切線混亂。另有「左轉前直近可進入」例外【需核實】。
- **具體修正方法**：關卡開場顯示情境時鐘牌（「平日 8:15」/「週日 14:00」），做成兩個變體關：管制中（須行右線）＋非管制（可行左線，且目標左轉須入左線）；回饋文案列明「平日 7:30–9:00・17:30–19:00（以沖繩縣警最新公告為準）」並注明週日假日不實施。
- **修改優先程度**：P1。
- **預期改善效果**：由「認顏色」升級為「認時段＋讀路牌」，符合真實決策。

### P-17 狹路會車條文引用偏弱 — 優先度 P2
- **現有問題**：引用「道路交通法第18条・第27条」；第27条實為「被追及車輛的讓道義務」，與狹路會車（離合）場景不直接對應。
- **問題原因**：條文選取欠精確。
- **對玩家訓練的影響**：小；但本產品以「可核實法規」為賣點，引用必須嚴謹。
- **具體修正方法**：由法規顧問核實後改引（候選：第18条〔靠左〕＋第70条〔安全運転義務〕；坡道會車另有第34条第6項相關規定【需核實】）；全部 27 關條文做一次法務抽查清單。
- **修改優先程度**：P2。
- **預期改善效果**：教學內容經得起查證。

### P-18 難度 1 僅 2 關且已含交通 — 優先度 P0（資料改動為主）
- **現有問題**：系列頭兩關（T字左轉、T字紅燈右轉）已有對向車＋橫向車＋限速；沒有零壓力熟習關。
- **問題原因**：關卡表缺「第 0 階段」。
- **對玩家訓練的影響**：從未摸過右軚/靠左的玩家第一關就要同時處理轉向、讓行、信號——認知過載，前期挫敗流失。
- **具體修正方法**：新增 4 個 Stage 0 關（純資料＋現有路型即可）：①直路起步—巡航—停止線前停定（教起步/煞車距離，P-01/02 後尤其必要）；②直路車道保持（輕度左右修正，偏出車道線扣分）；③空路口左轉（無 NPC，教轉彎半徑與「勿蕩對面線」）；④空路口右轉＋打燈（配 P-06）。
- **修改優先程度**：P0。
- **預期改善效果**：操作與規則分階段學；後續關卡失敗歸因清晰（是不會操作還是不懂規則）。

### P-19 全部關卡同一路口、無連續路線 — 優先度 P2（工程量大）
- **現有問題**：27 關共用 CX=400/CY=520 幾何，玩家永遠由南向北；每關 30–60 秒單一路口。
- **問題原因**：場景引擎按單路口設計。
- **對玩家訓練的影響**：無法訓練「連續決策」（過完一個路口馬上準備下一個）、路線記憶與導航——真實駕駛的認知負荷主要來自連續性。
- **具體修正方法**：分兩步：(1) 低成本——把 WORLD_HEIGHT 由 1000 加至 3000，單關串 2–3 個既有路口模板（資料層加 `segments: RoadType[]`，evaluate 邏輯按段切換），做 3 個「綜合路線關」作各階段結業試；(2) 中期——抽象出 `junction` 物件陣列取代全域常數（CX/CY/STOP_LINE_Y 參數化），支援東西向進場與彎道路段。
- **修改優先程度**：P2（第 (1) 步可提前至 P1）。
- **預期改善效果**：結業試具備真實感；「錯過路口」「導航改道」等關卡（P-11）獲得舞台。

### P-20 燈號時序固定且短 — 優先度 P2
- **現有問題**：如第 2 關固定 3.2 秒轉青、第 12 關固定 4.2 秒；重玩即可背時間。
- **問題原因**：`lightChanges` 為固定 `atMs`。
- **對玩家訓練的影響**：玩家學會「數秒起步」而非「看燈起步」；且 3–5 秒的紅燈遠短於現實（那霸大路口紅燈 60–120 秒），養成「紅燈很快就過」的錯誤耐性預期。
- **具體修正方法**：`onStartDriving` 排程時對每個 `atMs` 加 ±35% 確定性抖動（以關卡 id hash 為種子的 session 隨機，同一次嘗試內固定、重試時不同）；「耐心等候」主題關（12、24）把首個綠燈延至 15–25 秒並在文案講明「現實沖繩市區紅燈可達 2 分鐘」。
- **修改優先程度**：P2。
- **預期改善效果**：反背版；耐性訓練名實相符。

### P-21 教學順序：右轉讓對向過遲 — 優先度 P0（重排即可）
- **現有問題**：第37条（右轉讓對向直行）是日本右軚駕駛最重要規則，但首次出現在第 14 關；其前第 2、6 關已要求右轉。
- **問題原因**：排序只按 difficulty 數字，未按知識依賴。
- **對玩家訓練的影響**：玩家在未建立「右轉＝讓」心智前已完成多次右轉（且第 6 關還是矛盾的箭頭關），先入為主。
- **具體修正方法**：按第 7 節新關卡流程重排 `drivingScenarios` 陣列順序（排序已是穩定排序，直接調檔案內順序＋難度值即可）；規則主題順：靠左/轉彎 → 信號 → 一時停止 → 讓行人 → **右轉讓對向** → 優先權 → 環境。
- **修改優先程度**：P0。
- **預期改善效果**：知識依賴鏈正確；第 14 關前置後，第 6、15、16、27 關成為它的變式練習。

### P-22 難度曲線靠 NPC 數量堆疊 — 優先度 P2
- **現有問題**：`enhance` 對 difficulty 3 一律 busy＋complex；「難」= 車多，而非決策更難。
- **問題原因**：難度模型單軸。
- **對玩家訓練的影響**：車多但行為可預測（多數 cruise 直線），視覺壓力≠判斷難度；真正的難（視線遮蔽、多重讓行排序、時序陷阱）未被系統化。
- **具體修正方法**：為 `Scenario` 增 `challenge: ('traffic'|'occlusion'|'timing'|'multi-yield'|'weather')[]` 標籤，每關至多兩軸；難度值 = 軸數＋NPC 密度綜合；審表確保每軸有由淺入深至少 3 關。
- **修改優先程度**：P2。
- **預期改善效果**：難度提升有明確教學含義，弱項分析可對應到軸。

### P-23 車體比例失真＋圓形碰撞 — 優先度 P1
- **現有問題**：玩家車約 32×52px（按比例 3.7m 寬——真車約 1.7m），車寬佔 40px 車道的 80%；碰撞用圓形半徑（bus 長 76px 卻用 r=24），長車頭尾大段無碰撞。
- **問題原因**：美術可讀性優先；碰撞取最簡實作。
- **對玩家訓練的影響**：距離判斷（會車間隙、跟車、泊位）無法遷移；視覺已擦到巴士卻不算撞，破壞「距離感」教學。
- **具體修正方法**：(1) 車寬縮至 20px（保長 52），車道維持 40px——寬佔比降至 50%，接近真實（1.7m/3.25m≈52%）；NPC 同步縮放；(2) 碰撞改 OBB（矩形＋rotation，Phaser `Phaser.Geom.Intersects.RectangleToRectangle` 不支援旋轉，需自寫 SAT 分離軸，約 60 行，或每車用 2–3 個圓串近似）；(3) 泊車模組（P-10）強制依賴此項。
- **修改優先程度**：P1。
- **預期改善效果**：會車、跟車、泊位的空間判斷開始有遷移價值。

### P-24 高速轉向過敏 — 優先度 P2
- **現有問題**：轉彎半徑 = speed/TURN_RATE，80km/h 時約 77px ≈ 9 米（真車 80km/h 安全轉彎半徑 200 米級）。
- **問題原因**：`speedFactor` 封頂於 1，未隨速度衰減轉向率。
- **對玩家訓練的影響**：高速公路關可以電玩式急扭而不失控，車速感與「高速＝方向盤動作要小」的核心認知相反。
- **具體修正方法**：速度高於巡航後令轉向率衰減：`turnRate *= CRUISE_SPEED / max(speed, CRUISE_SPEED)`（半徑隨速度平方增長）；並加側滑判定：高速大角度轉向時觸發打滑（短暫失控＋螢幕提示），雨天閾值更低。
- **修改優先程度**：P2。
- **預期改善效果**：高速關訓練「預判與微調」，並為雨天濕滑提供機制載體。

### P-25 狹路不狹 — 優先度 P2
- **現有問題**：NARROW_ROAD_W=56px ≈ 6.5 米，實為標準雙線寬；「單車寬」名不副實。
- **問題原因**：遷就車體過大（P-23）。
- **對玩家訓練的影響**：會車只需直行微讓即可，無「入待避位等對向」的真實決策。
- **具體修正方法**：P-23 縮車後把狹路降至 34px（≈4 米）；擴大現有待避灣並使其成為必用機制：對向車逼近時，唯一不判 `failed_to_yield` 的方案是停入待避灣；加牆邊刮擦判定（車身觸牆＝失敗，新原因 `'scrape'` 或複用 off_road）。
- **修改優先程度**：P2（依賴 P-23）。
- **預期改善效果**：還原沖繩巷道會車的真實壓迫感與決策。

### P-26 錯誤回饋非位置特定 — 優先度 P1
- **現有問題**：`FeedbackModal` 顯示的講解是關卡級靜態文字（成功失敗同一段）；錯誤位置無標示；`REASON_ADVICE` 僅在總結算頁出現。
- **問題原因**：回饋資料掛在 Scenario 而非 Outcome。
- **對玩家訓練的影響**：使用者要求的「錯誤位置／原因／現實後果／正確處理／下次觀察重點」五要素，目前只覆蓋「原因」一項。
- **具體修正方法**：(1) `resolve()` 時記錄失敗座標與各 NPC 位置快照，`FeedbackModal` 加迷你俯視圖（SVG 重繪路口＋紅 ✗ 標失敗點＋相關 NPC 位置）；(2) `FeedbackContent` 增結構化欄位 `{ consequence, correctAction, watchNext }`（雙語），逐關補文案（27 關 × 3 欄，文案工作約 2 天）；(3) 把 `REASON_ADVICE` 同步顯示於 FeedbackModal；(4) 加「重播」按鈕：以 2 倍速重演最後 5 秒（逐幀記錄 car/NPC 位置環形緩衝即可，無需完整 replay 系統）。
- **修改優先程度**：P1。
- **預期改善效果**：五要素回饋齊全；「知道錯在哪一米」是駕訓回饋的黃金標準。

### P-27 最高連擊顯示錯誤 — 優先度 P0（一行修復）
- **現有問題**：`ResultsScreen` 的 `maxStreak = session.streak`——顯示的是最終連擊；最後一關失敗則永遠顯示 0。
- **問題原因**：store 未追蹤 bestStreak。
- **具體修正方法**：`gameStore.recordAnswer` 加 `bestStreak: Math.max(bestStreak, streak)`；結算頁改讀 bestStreak。
- **對玩家訓練的影響**：小（數據可信度）。
- **修改優先程度**：P0（順手修）。
- **預期改善效果**：統計正確。

### P-28 無進度保存 — 優先度 P1
- **現有問題**：刷新即失去全部成績與弱項紀錄。
- **問題原因**：無持久層。
- **對玩家訓練的影響**：跨日訓練曲線無法累積，「行前達標」（第 7 節）無從判定。
- **具體修正方法**：`zustand/persist` middleware 存 localStorage：每關最佳五維成績、嘗試次數、失敗原因累計、各階段結業狀態；主選單顯示總進度環＋「距離行前達標還差 N 項」。
- **修改優先程度**：P1。
- **預期改善效果**：訓練變成可追蹤的課程。

### P-29 語言標籤與文本不符 — 優先度 P2
- **現有問題**：`zh-TW` 語言包實為粵語口語（「唔好蕩去對面」「煞唔切」）。
- **問題原因**：目標用戶為香港玩家但沿用 zh-TW 標籤。
- **對玩家訓練的影響**：台灣用戶閱讀障礙；語言檔命名誤導維護者。
- **具體修正方法**：改標籤為 `zh-HK`；如需覆蓋台灣用戶另出書面語 `zh-TW` 包（27 關 × 4 欄文案翻寫，約 2 天）。
- **修改優先程度**：P2。
- **預期改善效果**：受眾明確、i18n 規範。

### P-30 README／死代碼與實作不符 — 優先度 P2
- **現有問題**：README 稱「左轉關卡要求左後盲點確認」（實際僅環島關）；`signs`（僅第 26 關設值、從不渲染）、`decisionNodes`、`PedestrianLightState`、路型 `skewed`/`tunnel` 均為死欄位。
- **問題原因**：迭代殘留。
- **對玩家訓練的影響**：對玩家無直接影響，但誤導後續開發與驗收。
- **具體修正方法**：P-08/P-13 落地後 README 同步改寫；未排期實作的欄位（decisionNodes、tunnel、skewed、pedestrian light）先從型別移除或標 `@planned` 註釋；建立「型別欄位 ⇄ 場景實作」對照表納入 PR 檢查。
- **修改優先程度**：P2。
- **預期改善效果**：文檔可信，型別即規格。

## 7. 建議的完整關卡流程（六階段，共約 40 關）

> 通關規則：每階段須全部關卡「法規＋安全兩維滿分」方可解鎖下一階段（其他維度 B 以上）；失敗即重試（P-05）；每階段末設「結業路線關」（P-19 第 1 步）。

**Stage 0 右軚熟習（4 關·新）**：S0-1 起步煞停 → S0-2 車道保持 → S0-3 空路左轉 → S0-4 空路右轉＋打燈
　學習目標：油門/煞車/軚/打燈、靠左、轉彎半徑、煞車距離。

**Stage 1 信號與停止（6 關）**：現 2（紅燈右轉等待）→ 現 4（前車衝黃燈）→ 現 17（黃燈抉擇）→ 現 7（紅閃）→ 現 8（止まれ左轉）→ 新·煞車距離體驗
　學習目標：讀燈不背秒（P-20）、一時停止「線前停穩」（P-04）。

**Stage 2 讓行判斷（7 關）**：現 5（左轉讓行人）→ 現 10（學校區）→ **現 14（右轉讓對向·前移）** → 現 16（兩輛對向）→ 現 6（右箭頭·修正後）→ 現 26（左方優先）→ 現 9（狹路會車·P-25 改窄後）
　學習目標：行人一時停止（P-03）、第37条內化、無號誌優先權。

**Stage 3 市區實戰（8 關）**：現 1（T字左轉）→ 現 3（跟前車判斷）→ 現 13（小路出大路）→ 現 19（停車場出口）→ 新·遮蔽止まれ → 現 11（單行路）→ 現 21＋新變體（巴士線兩時段）→ 現 12/24 合併（長紅燈）→ 結業路線關①
　學習目標：探頭確認（P-07）、視線受限決策、讀路牌。

**Stage 4 幹道與環境（8 關）**：現 27（右轉專用線·P-13 激活後）→ 現 25（環狀交差點）→ 現 22（ETC＋合流）→ 現 23（高速巡航）→ 新·高速切線 → 現 20（雨天右轉）→ 新·夜間 → 新·逆光 → 結業路線關②
　學習目標：車線選擇、高速紀律、環境減速。

**Stage 5 突發應變（4 關·新）**：前車急停 → 救護車 → 道路工程 → 錯過路口/導航改道
　學習目標：冷靜程序（評分掛平穩度與程序，不掛時間）。

**Stage 6 泊車（3 關·新）**：空場倒車入位 → 兩側有車入位 → 滿位巡場
　學習目標：倒車視角、車身感、滿位不慌。

**行前達標標準（完成訓練的定義）**：
1. 全部六階段結業；2. 一時停止關 10 次連續「線前完全停穩」；3. 右轉讓對向連續 5 次空檔選擇正確且決斷延遲 <2 秒；4. 全部左轉關盲點確認使用率 100%；5. 雨天＋夜間關各以安全滿分通過；6. 倒車入位 3 次内 2 次一把入；7. 綜合路線關②一次通過。達標後顯示「行前準備完成」證書頁（附「遊戲不能取代實路經驗」免責提示）。

## 8. 玩家評分及錯誤回饋系統（設計規格）

**逐關五維評分（P-09）**：安全／法規／觀察／速度／決斷，各 0–100，星級=五維均值（≥90 三星、≥70 兩星）。連擊倍率保留但只影響「娛樂積分」，不影響能力評級——兩套分數並列顯示。

**錯誤五要素回饋（P-26）**，失敗時 FeedbackModal 依次顯示：
1. **位置**：迷你俯視圖標 ✗ ＋最後 5 秒重播；
2. **原因**：現有 reason 標籤＋觸發時的關鍵數據（「越線時車速 34km/h／燈號：紅」）；
3. **現實後果**：新欄位 `consequence`（「一時不停止：罰款 7,000 円、扣 2 分；與橫向車碰撞多為對方優先，保險免責額自付」——金額需以現行反則金表核實）；
4. **正確處理**：新欄位 `correctAction`（程序化步驟 1-2-3）;
5. **下次觀察重點**：新欄位 `watchNext`（「進入此類路口先看：停止線位置→右方來車→左方來車→再右一次」）。

**結算頁**：五維雷達圖＋弱項卡（保留現有 reason 統計）＋「針對練習」一鍵重練（P-05）＋歷史曲線（P-28）。

## 10. 最終優化方案（路線圖）

- **R1「糾正負遷移」＝P0 全項**。驗收標準：新玩家不看說明玩 Stage 0–1，能自然形成「提前煞車、線前停穩、見行人停定、轉彎先打燈」四個行為；`speeding`/`no_signal` 判定在測試中可被實際觸發。
- **R2「從測驗到訓練器」＝P-07/08/09/26/05 深化**。驗收標準：同一玩家重玩同一關，第二次成績因行為改善而非背版提升（燈號抖動 P-20 提前納入）；每次失敗都能說出「哪裡、為何、下次看什麼」。
- **R3「內容補全」＝泊車、突發、夜間/逆光、巴士時段、車道**。驗收標準：第 7 節六階段全部可玩，行前達標流程走通。
- **R4「沉浸與規模」＝連續路線引擎、橫式信號、比例修正、i18n、持久化完善**。驗收標準：三個結業路線關串聯 3 路口以上；美術通過「沖繩街景對照」抽查（信號橫式、反射鏡、石灰岩淺色路面）。

**團隊分工摘要**：
- 程式：物理常數校正（R1，2 天）→ 判定邏輯（R1，3 天）→ 評分/回饋管線（R2，1 週）→ 遮蔽渲染與 OBB（R2–R3，2 週）→ 倒車與泊車場景（R3，1.5 週）→ 多路口引擎（R4，2 週+）。
- 遊戲設計：關卡表重排與 Stage 0/5/6 劇本（R1–R3）；難度標籤體系（R2）；達標標準數值化（R3）。
- 美術：橫式信號、反射鏡、救護車、工程路障、泊車場 tile、夜間/逆光效果（R2–R4）。
- 文案/法務：27 關 `consequence/correctAction/watchNext` 三欄補寫；第 4 節【需核實】6 項查證（沖繩縣警、e-Gov 法令檢索）；反則金金額核實。
